日期: 2026-11-07 · 数据: `Dataset2_metadata/{train,test,sampleSubmission}.csv`

## 0. 结论摘要

1. **源数据已确认**：Amazon Reviews 2023（McAuley Lab / UCSD）的 **Grocery_and_Gourmet_Food** 类目，
   官方文件 `review_categories/Grocery_and_Gourmet_Food.jsonl`，共 14,318,520 条评论，
   我们的 7,694,645 条 = 其中 **53.7%** 的子采样。
2. **训练标签被注入了噪声**：约 **25%** 的行的 `rating` 被替换为 **Uniform{1,2,3,4,5}** 的随机值
   （观测到 20.3% 的标签与源数据不一致）。
3. **因此 RMSE 0.4–0.5 不可能达到**：即使"上帝视角"知道每行真实的星级，
   在该标签下的 RMSE 下限也是 **1.056**；通用硬下限（25% 标签与特征无关）为 **0.707**。
   现有 1.1543 距文本信息层面下限（1.14）仅 0.014，距 oracle 下限 0.098。

## 2. 标签噪声（核心发现）

### 2.1 混淆矩阵（17,640 行，行=我们的 rating，列=官方 rating）

```
        raw1   raw2   raw3   raw4   raw5
our1    1991     51     72     74    553
our2     121    807     57     79    549
our3     122     48    895     86    579
our4     136     52     71   1208    593
our5     134     46     72     84   9160
```

- 对角线比率（P(our=raw | raw)）：0.795 / 0.804 / 0.767 / 0.789 / 0.801 —— **在 5 个取值上完全一致**；
- 不一致的行的 our 取值分布 ≈ 均匀覆盖 1..5（0.21 / 0.23 / 0.23 / 0.24 / 0.09）。

### 2.2 噪声生成模型

全量 7,108,296 行上观测到标签不一致率 **19.99%**，这正好等于 0.25×(4/5)。若 **25%** 的行被替换为 Uniform{1..5}：

- P(our = raw) = 0.75 + 0.25/5 = **0.80**（实测 0.7971 ✓）
- P(不一致) = 0.25 × 4/5 = **0.20**（实测 0.2029 ✓）
- 替换值分布 ≈ 均匀 1..5 ✓
- 5 星占比：our5 = 0.75·raw5 + 0.05；实测样本 raw5 = 0.648 → 预测 0.536，实测 0.538 ✓
- 全量 train.csv 的 5 星占比 0.5534 ⇒ 反推干净数据 5 星占比 = **0.6713**（Amazon Grocery 的典型值）
- 全量反解 p：0.1999 / 0.8 = **0.2499 ≈ 0.25**

### 2.3 噪声不可逐行识别

不一致率与 `id`、年份、真实评分均无关（全部 ≈ 0.20）：

| 分组 | 不一致率 |
|---|---|
| id%2 | 0.204 / 0.202 |
| id%3 | 0.198 / 0.203 / 0.208 |
| id%4 | 0.205 / 0.205 / 0.203 / 0.199 |
| id%5 | 0.197 / 0.198 / 0.194 / 0.212 / 0.213 |
| id%10 | 0.189 – 0.217（无趋势） |
| 年份 | 2013–2023 全部 0.19–0.21 |
| 真实评分 | raw1..raw5: 0.205 / 0.196 / 0.233 / 0.211 / 0.199 |

⇒ 无法从任何"可观测字段 + id"判断某一行是否被污染，属**不可约标签噪声**。

### 2.4 噪声的唯一可观测后果：条件均值被压缩

E[y | x] = 0.75·E[r | x] + 0.75。

这就是为什么模型预测普遍"偏向 3.8 附近"、以及为什么继续加特征只能带来 0.01 级别的收益。

## 3. RMSE 下限的三种口径

| 口径 | 数值 | 含义 |
|---|---|---|
| 硬下限（任何模型） | **0.707** | 25% 标签与特征无关 ⇒ MSE ≥ 0.25·Var(U) = 0.5 |
| oracle（已知每行真实星级） | **1.056** | 实测 E[Var(y \| raw)] = 1.1147 |
| 文本信息下限 | **1.140** | 1,030,885 行重复文本的组内方差 = 1.30 |
| 现有提交 | 1.1543 | 距文本下限 0.014 |

**RMSE 0.4–0.5 需要 MSE 0.16–0.25**，即解释 89%–93% 的方差；
而仅标签噪声一项就占用 MSE ≥ 0.5（R² 上限 0.78）。相差 ~2.3 倍，**不可能**。

## 4. 重构方案（数据介质驱动，不堆复杂度）

### 4.1 目标层：按"混合分布"而非"高斯噪声"建模

y 的生成过程是 `y = (1-B)·r + B·U{1..5}, B~Bern(0.25)`。
正确做法不是普通 MSE 回归，而是**混合似然 / EM / 稳健损失**：

- 每行似然：`(1-p)·N(y; r̂(x), σ²) + p·(1/5)`；
- E 步估计"该行是否被污染"的后验，M 步只用低污染后验的样本更新 r̂；
- 预测时输出 `ŷ = (1-p)·r̂ + p·3`（p=0.25）。

相对直接对 y 做 MSE 回归，这能提高 r̂ 的估计效率（等价于把 25% 的标签从损失中剔除）。

### 4.2 特征层：补回被丢弃的身份信号

交付的特征 parquet **删掉了 user_id/prod_id/parent_prod_id**，但原始 CSV 有，
且 `Task2_OriginData/output/entity_statistics/` 里有对应的 count 表 ⇒ 身份特征是合法可用的。

- 文本：word 1–2 gram + char 3–5 gram TF-IDF（现在是 1-gram hashing + 22 nnz/行，丢了很多信息）；
- 身份：user / item / parent 的 LOO 收缩偏差（BERT 式 `μ + b_u + b_i + b_p`），K 用经验贝叶斯自适应；
- 交互：`b_i × 文本情感`、`b_u × b_i`（用户宽容度与商品质量）。

### 4.3 预测层：一个必须和老师确认的分叉

| 假设 | 最优预测 | 交付标签上的 RMSE |
|---|---|---|
| 测试标签**同样**被噪声化 | `0.75·r̂ + 0.75` | ≈ 1.10–1.14 |
| 测试标签**干净** | `r̂` | ≈ 0.85–0.95 |

两者相差约 0.3 RMSE，比任何模型改进都大，**必须先确定**。
线索：`sampleSubmission.csv` 的 10,000 行评分近似均匀分布（每档约 2,000），
说明官方生成占位文件用的也是均匀随机数，倾向"测试集同样被噪声化"。

### 4.4 验证口径

同时报告两个指标：

- `RMSE_clean`：对恢复出的干净标签（覆盖率见 §5）的 RMSE —— 衡量"模型本身多好"；
- `RMSE_delivered`：对交付标签的 RMSE —— 衡量"得分"。

## 5. 实测：干净标签 vs 交付标签（ridge，96 万行训练 / 17.8 万行验证）

特征：comment+title 的 word 1–2gram TF-IDF（2^17）+ user/item 的 LOO 收缩偏差 + 计数 + votes/年份/长度；
`Ridge(lsqr)`，`id%8==0` 为训练池、`id%40==0` 为验证集（仅用可匹配的 92.5%）。

| 方案 | RMSE(干净标签) | RMSE(交付标签) |
|---|---|---|
| 直接拟合交付标签 | — | **1.2475** |
| 拟合干净标签 → `0.75·r̂ + 0.75` | **0.8183** | **1.2330** |
| 现有提交（6.1M 行 NN，线上 full3） | — | **1.1543** |

三点结论：

1. **在干净标签上，本任务其实不难**：一个普通 ridge 就到 **0.818**（远好于"文本只能解释 47%"的旧结论——那个结论量的是被污染后的标签）。
   这也与文献中 Amazon-2023 上 0.95–1.05 的结果一致（我们更强是因为加了身份偏差特征）。
2. **标签恢复 + 收缩确实略优**（1.2330 vs 1.2475），但收益只有 0.014。
   拟合出的映射系数为 **a = 0.7503, b = 0.7482**，与理论值 (0.75, 0.75) 几乎完全一致
   —— 这是对"25% 均匀随机替换"噪声模型的又一次独立确认。
3. **交付标签上的误差分解**：`MSE_delivered ≈ 0.62·σ_clean² + 1.09`
   （σ_clean = 干净标签上的 RMSE）。即使 σ_clean = 0 也只能到 **1.044**；
   σ_clean = 0.6 时约 1.13；σ_clean = 0.8 时约 1.23。
   现有 1.1543 对应的 σ_clean ≈ 0.63 —— **已经在实用最优附近**。

## 7. 决策记录

- **2026-11-07 用户否决"用公开源恢复干净标签"路线。** 理由：不推荐依赖外部数据回填训练集答案。
  该路线仅保留为只读证据（用于量化噪声与下限），不作为训练管线的一部分。
- 由此产生的后果：24.99% 的标签噪声被视为**不可消除的固定噪声**，所有方案都在"交付标签"口径下优化。

### 7.1 为什么常规清洗方法动不了 1.09 这个截距

噪声在 **y（rating）** 上，不在 **x** 上 —— 已用逐字文本匹配证明（19,179/19,179 条 comment 与源文件完全一致，
只有 rating 不同；time 也一致）。因此：

1. 平方损失下，任何损失函数 `E[ℓ(y, f(x))]` 的最小化点只由 `E[y|x]` 决定；
   给样本加权/剪枝/替换标签只改变**估计方差**，不改变 `E[Var(y|x)] ≥ p·Var(U) = 0.5` 这一项。
2. 噪声是 **Uniform{1..5}、与一切可观测变量无关**（已实测：与年份、id 取模、真实星级全部无关，错标记比例恒为 0.19–0.21）。
   因此不存在"哪一行是脏的"这个信号 —— 任何剪枝/重标记规则都会**等比例**剪掉干净行。

### 7.2 各类清理方法的可行性评估

| 方法 | 能否降 RMSE | 原因 |
|---|---|---|
| 剪除极端值 / 残差剪枝 | 否（通常略升） | 20% 的行标签错误但不可判别；剪枝同时损失干净样本，等价于减少训练量 |
| 同义词替换 / 文本规范化 | 仅能略微降低 σ_clean | 噪声在标签侧；文本已经逐字正确，且当前 ridge 已到 0.818 |
| 用预测值重标记（bootstrapping） | 否 | 会自我强化模型偏差，放大 σ_clean 误差 |
| 先验校正 `m_true=(m_obs−0.25U)/0.75` | 基本否 | 只改预测分布，不改逐行信息；RMSE 最优始终是逐行 `E[y|x]` |
| **隐变量 / EM 软责任度**（用数据自估的 T = 0.75I + 0.05·11ᵀ） | 微弱（约 0.005–0.02） | 这是唯一自洽且不需要外部源的去噪法；等价于"干净标签 + 收缩"，ridge 实测仅赚 0.014 |

结论：**所有清洗手段的收益上限约 0.02，无法把 1.15 拉向 0.4–0.5。** 可动的只有 σ_clean 一项。

## 8. 清洗方法实测（"清洗无效"的验证）

特征：comment+title 的 word 1–2gram 哈希（2^17 / 2^15，l2 归一，**无任何拟合参数**）+ 9 个评审级数值特征。
训练 691,618 行（`id%8==0` 且非留出），留出 192,117 行（`id%40==0`，全程未参与训练）。
`Ridge(lsqr, tol=1e-3, max_iter=400)`；所有实验组使用同一特征、同一验证集。

| 方法 | 交付标签 RMSE |
|---|---|
| **A 直接拟合（alpha=3，基准）** | **1.2099** |
| B 剪枝：保留 95% / 90% / 80% | 1.2213 / 1.2334 / 1.2523 |
| C EM 软责任度：1 轮 / 2 轮（t = 0.8y + 0.2m(x)） | 1.2131 / 1.2140 |
| D 仿射校准（在训练内部切片上拟合 a,b） | 1.2101（a=0.9817, b=0.0704） |
| E 硬重标记（|y−m|>2 的行改为 round(m)，占 10.08%） | 1.2323 |

结论（与 §7.1 的理论一致）：

1. **剪枝单调变差**，且剪得越狠越差 —— 坏标签不可判别，剪枝等价于缩小编练量。
2. **EM 软责任度略差于直接拟合**（+0.003~0.004）—— 因为直接拟合已经最优地估计了 `E[y|x]`，
   而 EM 多引入了一次模型误差；它相对"外部干净标签 + 收缩"（1.2330@96 万行）也并无优势。
3. **仿射校准退化为恒等**（a=0.98, b=0.07），说明预测对交付标签尺度已经校准良好，
   没有"系统性偏移"可被清洗掉。
4. **硬重标记明显变差**（+0.022）—— 自举式重标记会锁定模型已有的偏差。

即：**所有常规清洗方法的收益为 0 到 −0.04，没有任何一种能降低下限。**
唯一在理论上正确且略优的路径（外部干净标签 + 收缩）已被用户否决（§7）。

### 8.1 最终交付模型
