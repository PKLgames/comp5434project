# 数据探索经验记录（Dataset 2 / COMP5434）

本文件只记录**可复用的经验结论**，不重复证据链（证据见 `SOURCE_AND_LABEL_NOISE.md`）。

---

## 1. 同义词替换 / 文本规范化：收益被高估，且有副作用

**结论：不要在这套数据上把清洗预算花在"改写文本"上。**

理由（均为本数据集上的实测）：

| 观察 | 数值 |
|---|---|
| 噪声位于标签侧还是文本侧 | 文本侧 **0** 噪声：19,179/19,179 条 comment 与官方源逐字一致，`time` 也一致，只有 `rating` 不同 |
| 文本侧现状 | 已经是语言无关的 `[\p{L}\p{N}]+` 分词、小写、不删停用词、不词干化 |
| 文本-only ridge（缓存特征） | 1.2140（对照：常数 1.5151、dense-only 1.8732） |
| 文本 + dense  ridge | 1.2335 —— **加入噪声特征反而变差** |

- 改写文本只能改善 σ_clean 这一项，而该项已经被文本特征本身主导；同义词替换会抹掉 **否定词、程度副词、比较级**（"not good" vs "good"、"slightly sweet" vs "very sweet"），在评分任务上这是净损失。
- 文本规范化的另一类收益（降维、拼写纠错）在这里边际很小：词表已由 hashing 固定，重复度低（唯一文本占 86.3%）。
- 真正值得做的文本侧动作是**扩大表征**（1–2gram、字符级、预训练句向量），不是"清洗"。

## 2. 身份特征（user / product 统计）：不要当主力

**结论：身份特征在本数据集上只能贡献约 0.05 RMSE，且存在"验证集虚高"的结构性风险。**

实测（全量 7.68M 行，按 `id%40==0` 留出 19.2 万行验证）：

| 模型 | RMSE |
|---|---|
| 常数（训练均值 3.842） | 1.5167 |
| 商品均值 | 1.4846 |
| 父子商品均值 | 1.4861 |
| 用户均值 | 1.5028 |
| 用户 + 商品 | 1.4725 |
| 全部身份偏差 + 计数 | **1.4698** |

为什么弱：

- **用户平均只有 1.64 条评论**（中位数 1），验证集有 **43.8% 的用户从未在训练集出现** → 用户均值几乎无法估计。
- 商品平均 12 条评论（中位数 3），可用但信息量有限。
- 全部 26 个 dense 特征与 rating 的 |相关系数| 均 ≤ 0.11（最大：log_comment_char −0.108、has_votes −0.106、votes_log −0.100、user_review_count_log +0.063）。

结构性风险（比"收益小"更重要）：

- 交付数据的**验证/训练**特征里，计数是用 80% 训练切分统计的；而**测试集**的计数是用一个**大得多的参考表**统计的（`user_unseen` 0.478 vs 0.090、`user_review_count` 4.19 vs 6.13）。
- 也就是说：身份特征在**验证集上会偏乐观**，在**测试集上会缩水**。任何"加大身份特征"的路线都会在本地看起来更好、提交后回落。
- 正确做法：保持低权重，或直接用文本 + 商品级弱信号；**不要**构建 user embedding / 用户历史序列模型。

## 3. 其他值得留存的探索结论

- **重复文本**：13.41% 的行落在重复文本组里，池化组内 sd 1.1424；这决定了"只看文本"的信息上限 ≈ 1.10–1.15。
- **标签噪声**：约 25% 的行 rating 被替换为均匀 1–5，与年份、id、真实星级全部无关 → **无法逐行识别**，因此剪枝/重标记类清洗无效（见 `SOURCE_AND_LABEL_NOISE.md` §7）。
- **id 结构**：train/test 的 `id` 各自是 0..N−1 的连续索引，**不可跨文件比较**；实体 id 是 16 位匿名哈希，不可还原。
- **工程约束**：本机 7 GB 内存，`pyarrow` 的 `to_pylist()` + `group_by` 在 768 万字符串上会 OOM；安全做法是流式 `open_csv` 分块 + 只保留 ID 级别的派生特征。Colab 可用于全量训练（见 `COLAB.md`）。
